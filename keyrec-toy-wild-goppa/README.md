# Wild Goppa key recovery over GF(4)

C++ experiments for wild Goppa codes
`Gamma(alpha, gamma^3) = Gamma(alpha, gamma^4)` over GF(4), with support in GF(64).
Each recovery uses **one held-out position and one holdout-kernel computation**.
A coherent local jet supplies both finishing methods:

- Quadratic bootstrapping, aligned tangent planes, a full minor GRS code, and
  Sidelnikov–Shestakov support recovery.
- Direct extraction from the ratio of two quadratic sections with adjacent
  contact orders.

The public generator and public parameters are the only recovery inputs.
The program returns an equivalent support, GRS multiplier, and monic irreducible
Goppa radical. It checks exact equality with the public GF(4) code using both
the cube and fourth-power descriptions.

## Build and run

Requires a C++17 compiler, M4RI, and `pkg-config` when using a system installation.
The recovery implementation does not invoke Sage or Python.

```sh
make
make check
./run.sh instances/a/public.txt runs/demo both
```

For the larger instance B, use OpenMP-enabled M4RI. On Linux with GCC, the
included helper builds the parallel library from a fixed source revision:

```sh
./build-openmp.sh
make -B M4RI_OMP="$PWD/deps/m4ri-omp"
./run.sh instances/b/public.txt runs/large both
```

The helper requires M4RI development headers, `curl`, and Python 3 for archive
extraction. The driver uses the available CPU count by default. `WILD_THREADS`
sets an explicit thread limit. Large matrices fail immediately with a
single-threaded M4RI build unless `WILD_ALLOW_SERIAL` is explicitly set. Reports
identify OpenMP support and the requested thread limit.

For a separate M4RI installation:

```sh
make M4RI_PREFIX=/path/to/m4ri
```

Use a fresh output directory. The final argument to `run.sh` is `minor`, `direct`,
or `both`. A combined run shares one kernel and one deep jet between the two
finishing methods. The driver checks the recovered keys using public data.

The kernel program reduces the GF(4) system through its binary expansion. It
exports a panel of 256 independent GF(4) kernel polynomials by default, selected
from distinct free columns with a fixed public shuffle. The full kernel dimension
and panel size are reported separately. Recovery verifies panel independence and
all original Hasse orders before checking the branch and continuation ranks.

`WILD_PANEL_SIZE` controls the number of exported polynomials, up to 4096.
`WILD_MATRIX_GIB` sets the packed-matrix allocation cap, defaulting to 16 GiB.
The packed matrices use approximately 0.10 GiB, 3.93 GiB, and 0.13 GiB for
A, B, and C respectively. Solver workspaces require additional memory.

To use an already computed kernel:

```sh
./build/wild-goppa recover instances/a/public.txt runs/demo/kernel.bin runs/replay both
```

This repeats public kernel verification and recovery, without another kernel
computation.

## Generate a key

The arguments are radical degree, length, holdout degree, random seed, and output:

```sh
./build/wild-goppa generate 4 64 4 1 runs/new-key
./run.sh runs/new-key/public.txt runs/new-key-recovery both
```

Generation checks irreducibility, the public dimension, and the wild Goppa
identity. The public matrix is saved separately from `audit/secret.txt`.

## Recovery steps

1. **One holdout system.** Retained unit columns permit the squarefree degree-`d`
   monomial space. Redundant derivative orders are omitted during construction;
   every order below `s` is checked on the exported panel. Each instance satisfies
   `s(n-1)>dD`, which proves curve vanishing by ordinary interpolation.
2. **Stationary quadratic separation.** Gradients give a four-dimensional kernel.
   Quadrics from polynomials whose gradient at the seed is zero have restriction
   rank three. The quotient multiplication maps recover the three branches by
   an eigenvalue calculation.
3. **Deep coherent continuation.** The fixed matrix combines the regular
   order-`r` equations with stationary order-`r+1` equations. Its kernel must be
   exactly the point/tangent plane on every branch. Each coefficient is recovered
   by linear solving, including after the coefficient span becomes full.
4. **Bootstrap/minor finishing.** Public-point evaluations and one jet prefix
   recover the complete quadratic ideal of the selected branch. The gradient
   kernel at every public point must be a plane. Square roots of all coordinate
   minors span a GRS code of dimension `D`, which is verified exactly.
5. **Direct finishing.** Quadratic sections have contact orders `2D` and `2D-1`.
   Their ordinary evaluation ratio is a Möbius transform of the support. This
   finishing step uses only the jet prefix through order `2D-1`.
6. **Wild Goppa description.** The sum of the public columns identifies the point
   at infinity on the reconstructed curve. After choosing that affine chart,
   fourth roots of the recovered multiplier times the support derivative
   interpolate the radical `gamma`. Its degree, irreducibility, and public-code
   equality are verified.

GF(4) continuation uses the stationary next-order equations. It does not impose
the binary relation `v_(2r)=v_r^2`. Square roots are used in the minor construction;
the direct support quotient is `R/S`.

## Independent verification

The C++ verifier reads only a public input and recovered key:

```sh
./build/wild-goppa verify instances/a/public.txt results/a/recovery/direct-key.txt
```

The independent verifier uses only Python's standard library and imports no
recovery code:

```sh
python3 verify.py instances/a/public.txt results/a/recovery/direct-key.json
python3 verify.py instances/a/public.txt results/a/recovery/minor-key.json
```

An optional audit checks global Frobenius/Möbius equivalence with the generated
secret:

```sh
./build/wild-goppa audit instances/a/public.txt instances/a/audit/secret.txt results/a/recovery/direct-key.txt
```

Public geometric certificates independently fit one scalar series and one
invertible parameter series to every recovered jet coefficient. They verify all
branch planes, the complete quadratic ideal, and tangent alignment. A fresh
polynomial multiplication checks the completed jet against every exported
holdout polynomial.

## Results and files

Saved reports, complete keys, jets, quadrics, tangents, and section coefficients
are in `results/`. The reports separate kernel acquisition from recovery and
verification. These are fixed toy examples, not statistical success estimates.

`instances/` contains public inputs and separate audit keys. `src/` and `include/`
contain the complete implementation. Temporary runs and compiled programs are
excluded from version control. See [FORMATS.md](FORMATS.md) for encodings.
